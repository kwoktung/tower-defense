# Spec: 水果皮肤（fruit）

Status: ready-for-agent

## Problem Statement

现在游戏只有 Polygon 皮肤：彩色多边形放在深色背景上。它适合调试和截图对照，但缺乏游戏感，玩家也难以和角色产生情感联系。ADR-0002 已经把"换美术只需新写一个 Skin"的抽象准备好了，但还没有一套真正的美术资源来验证它。另外，项目里还没有任何加载图片的流程：没有静态资源目录，没有图集，也没有处理 AI 生成图片的工具链。

## Solution

新增一套原创的 Q 版"水果守卫果园"皮肤 `fruit`：

- 三种塔是蓝莓射手、菠萝炸弹、柠檬酸汁，各 3 个等级。
- 三种敌人是毛毛虫、果蝇、硬壳甲虫。
- 地图是草地、泥土小路和土坑。

美术用 Gemini 网页版生成：先出一张风格样板，用户确认后再批量生成；然后用一条可复现的命令完成去背、缩放和打包图集。新皮肤通过 `?skin=fruit` 和 Storybook 的皮肤切换使用；默认皮肤仍然是 Polygon，整体验收后由用户决定是否切换。

## User Stories

### 玩家

1. 作为玩家，我希望塔是可爱的 Q 版水果角色，这样游戏更有亲和力。
2. 作为玩家，我希望一眼分清三种塔：蓝莓射手是蓝紫色，菠萝炸弹是黄色带叶冠，柠檬酸汁是黄绿色。
3. 作为玩家，我希望塔升级后外形有明显变化（更多叶子、装饰，满级有皇冠或金色点缀），这样我能看出哪些塔已经变强。
4. 作为玩家，我希望一眼分清三种敌人：毛毛虫、果蝇、硬壳甲虫；并且一看就知道甲虫的壳很硬（护甲）。
5. 作为玩家，我希望敌人走路时会上下弹跳，果蝇快、甲虫慢，这样画面是活的，速度差异也看得出来。
6. 作为玩家，我希望敌人朝着前进方向，往左走时转身，这样不会出现倒着走的怪物。
7. 作为玩家，我希望子弹分别是小蓝莓、菠萝块和柠檬汁滴，这样一看就知道是哪座塔打的。
8. 作为玩家，我希望命中和溅射时有对应颜色的果汁飞溅，击杀时有叶片或汁滴散开。
9. 作为玩家，我希望被减速的敌人身上有黄绿色的"酸汁"效果，这样我知道柠檬起作用了。
10. 作为玩家，我希望塔升级时有金色闪光，卖出时仍有"收缩 + 金币飘字"。
11. 作为玩家，我希望地图是草地、泥土小路和土坑，这样整体是一个果园，而不是抽象的格子。
12. 作为玩家，我希望鼠标悬停在可建造的土坑上时它会提亮，并显示射程圈，和现在的操作一样。
13. 作为玩家，我希望 HUD 和塔面板的配色换成温暖的果园色调，但布局和操作不变。
14. 作为玩家，我希望在大屏上画面依然清晰，不会糊。

### 开发者 / 美术

15. 作为开发者，我希望用 `?skin=fruit` 在游戏里切换到水果皮肤，并在 Storybook 的皮肤下拉框里选到它，这样我能逐个 story 对比两套皮肤。
16. 作为开发者，我希望默认皮肤仍然是 Polygon，直到用户决定切换，这样调试和截图的基线不变。
17. 作为开发者，我希望一条命令就能从原图重新生成图集，并且结果可复现，这样替换任何一张图都只是"换文件、重跑命令"。
18. 作为开发者，我希望原图不进 git，进 git 的是提示词记录和处理后的图集，这样仓库保持小巧，但美术是怎么来的有据可查。
19. 作为开发者，我希望图片通过模块导入加载，这样游戏、Storybook 和截图脚本都能用，不用改静态资源配置。
20. 作为开发者，我希望水果皮肤和 Polygon 一样，缺少某个 (kind, level) 的外形时会报 `console.error`，这样"所有塔种 × 所有等级"验收页能发现漏画。
21. 作为美术流程的执行者，我希望先出一张风格样板，并经用户确认，再批量生成，这样不会浪费免费额度去生成风格不对的图。
22. 作为美术流程的执行者，我希望每张图的提示词都被记录下来，这样以后补图或重做时能保持风格一致。

## Implementation Decisions

### 原创性

- 角色、名字和造型全部原创。提示词里不出现 "Plants vs. Zombies"、玉米射手、西瓜投手这类既有作品的名称或角色。
- 只借用"Q 版植物守卫"这一类型的感觉。

### 美术规格

- **画风**：Q 版扁平卡通，大眼睛，头身比约 1:1；粗的深色描边；柔和的赛璐璐阴影；四分之三正面视角，光从左上方来；颜色饱和明亮，不要写实纹理。最终以用户确认的风格样板为准。
- **背景**：所有角色、子弹和土坑都要求纯品红背景（#FF00FF），方便去背。纹理图（草地、泥土）要求可无缝拼接、俯视、没有角色。
- **朝向**：敌人统一画成面朝右，塔面朝前或略朝右。
- **尺寸**：处理后按显示尺寸的 2 倍保存。显示尺寸参考 Polygon 皮肤：塔 Lv1 约 40 像素，Lv3 约 50–56 像素；敌人约 28–36 像素；子弹约 10–16 像素；土坑约 54 像素。整张图集预计不超过 1024×1024。
- **清单**：

  | 类别 | 数量 | 内容 |
  |---|---|---|
  | 塔 | 9 | 蓝莓射手、菠萝炸弹、柠檬酸汁，各 Lv1–3 |
  | 敌人 | 3 | 毛毛虫、果蝇、硬壳甲虫 |
  | 子弹 | 3 | 小蓝莓、菠萝块、柠檬汁滴 |
  | 地图 | 3 | 草地纹理、泥土纹理、土坑 |

- **塔的等级**：先生成 Lv1，然后在同一个 Gemini 对话里基于它修改，得到 Lv2（加叶子或装饰）和 Lv3（皇冠或金色点缀），保持同一个角色。如果某一级改不像，就用 Lv1 的图加代码叠加（放大、描边、等级标记）来补，并在工单里记录。

### 生成流程（Gemini 网页版）

- 通过 Chrome 扩展操作用户已经登录的 Gemini 网页版。前提：用户已登录，并允许扩展访问 gemini.google.com；用户已确认可以接受 Google 对生成图片的使用条款。
- **先出风格样板**：一张图里放三个水果角色。用户确认后，后续每张图都在同一个对话里生成，并在提示词里要求"和样板保持同样的画风"。
- **下载与记录**：下载的原图移到仓库里一个不提交的原图目录；每张图的提示词、生成日期和是否做过修改，记录在提交的提示词记录里。
- **额度**：免费版每天能生成的图片数有限，可能要分两天做完。

### 素材生产线

- 一条命令（`pnpm art:fruit`）从原图生成图集，可复现。它调用 ImageMagick，依次做：
  - 去背：从四周往里填充去掉品红背景，再清理边缘的品红残留；
  - 裁掉多余的空白；
  - 按目标尺寸缩放，使用 Lanczos 算法；
  - 用简单的逐行排列把小图放进一张大图，输出图集 PNG 和 Phaser 能读的图集 JSON（hash 格式，帧名形如 `tower-basic-1`、`enemy-armored`、`projectile-slow`、`slot`）。
- 纹理图（草地、泥土）不进图集，单独输出成可平铺的小图。
- 个别图从四周填充去背效果不好时，可以对那张图改用 rembg，并在提示词记录里注明。
- 原图到帧名、目标尺寸的对应关系，写在一个提交到 git 的清单文件里；脚本按清单处理。

### fruit 皮肤

- 实现现有的 Skin 接口，不改接口。
  - `preload`：加载图集和纹理，图片通过模块导入获得地址。
- **地图**：
  - 背景用草地纹理平铺；
  - 路径的几何形状不变，填充改为泥土纹理；
  - 可建造的格子画土坑图，鼠标悬停时提亮；
  - 建造射程预览仍由皮肤用代码画（现有 MapView 的职责）。
- **塔**：
  - 每个 (kind, level) 一帧；`sync` 发现等级变化时换帧（ADR-0002）；
  - 开火时挤压一下；升级时弹一下，并有金色闪光；
  - 缺帧时画回退外形并报 `console.error`。
- **敌人**：
  - 不旋转；往左走时水平翻转，竖直路段保持之前的朝向；
  - 走路时上下弹跳，频率随速度变化；
  - 被打中时闪白，保留血条；
  - 被减速时显示黄绿色的酸汁环，并叠一层淡黄绿色；
  - 缺帧时画回退外形并报 `console.error`。
- **子弹**：按塔种用对应的帧，飞行时可以旋转。
- **特效**：全部用代码画，改用果汁配色：命中和溅射是对应塔的果汁色；击杀时汁滴或叶片散开；升级是金色闪光；卖出保持"收缩 + 金币飘字"。
- **Theme tokens**：换成温暖的果园色调（HUD 底色、按钮、文字、金币、范围圈、警示色），字体仍用系统字体。HUD 和面板的布局不变。
- **注册**：加入皮肤注册表；默认皮肤仍然是 Polygon。

### 不变的部分

- Simulation、内容数据、场景、HUD 和面板的布局、Debug overlay 都不改。按 ADR-0002，这次只新增 Skin 和资源。如果发现必须改其他层，要在工单里说明原因。

## Testing Decisions

- 没有新的规则，不新增 Simulation 测试。
- **视觉验收**：用 story 冒烟测试（不能有 `console.error`）和 Shots。
  - Storybook 的每个 story 都能切到 fruit 皮肤。
  - 截图脚本要能输出 fruit 皮肤的截图，至少覆盖：所有塔种 × 所有等级、各种敌人（含被减速和被打中）、子弹和特效、地图悬停、HUD 和塔面板、一个跑动中的 Scenario 时间线。如果截图脚本目前只用默认皮肤，需要让它支持指定皮肤。
- **缺帧检测**：临时删掉图集里的一帧，确认对应的 story 会失败；验证完恢复。做法和 armor-and-slow 02 号工单的检测一样。
- **生产线**：`pnpm art:fruit` 跑两次，生成的图集应该完全相同（可复现）。
- **试玩**：在 `pnpm dev` 里用 `?skin=fruit` 打一局，控制台没有报错。

## Out of Scope

- 逐帧动画（走路循环、开火动作帧）。
- 特效和 HUD 的手绘美术、自定义字体、音效。
- 按路段区分的路径图块（直道、拐角）。
- 把 fruit 设为默认皮肤（在整体验收后由用户决定）。
- 修改 Skin 接口、Simulation 或内容数据。
- 仿制任何既有作品（如《植物大战僵尸》）的角色。
