# 03 — 开波节奏的平衡验证

**What to build:** 在 `pnpm balance` 里加入"每次都提前叫波"的参考打法，确认提前叫波的奖励不会太高，现有验收标准仍然全部通过；需要时调整每只敌人的奖励或关卡。产出是一份记录，必要时附带数值调整。

参考 spec：`../spec.md` 的"平衡报告"。

**Blocked by:** 01 — 自动开波；02 — 提前叫波

**Status:** ready-for-agent

- [ ] 新增参考打法"混合打法 A，每次都提前叫波"：当前波一出完就叫下一波。报告里记录输赢、剩余生命、累计奖励，不设硬性标准
- [ ] 判断：
  - 如果它满血通关，而且累计奖励能多买好几次升级，说明奖励太高：调低每只敌人的奖励（或改成小数）、或者调整关卡，然后重跑
  - 如果它输了，说明提前叫波在第 1 关风险很大，这是可以接受的，记录下来
- [ ] 现有验收标准仍然全部 ok
- [ ] 在 ticket 评论里记录结果和结论；如果改了数值，同步更新 spec 和路线图的"观察"一节
