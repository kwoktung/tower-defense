# Spec: 开波节奏：自动开波与提前叫波

Status: done

## Problem Statement

现在每一波的开始都要玩家手动操作：上一波的敌人全部出完、场上清空后，玩家必须点"开始下一波"，否则游戏就一直停着。这有两个问题：

- **节奏拖沓。** 玩家专心升级、建塔时，常常忘了开波，游戏就停在那里。每一波结束都要多点一次按钮，打断了流畅感。
- **熟练玩家没法加快节奏。** 场上还有敌人时不能开下一波，所以"冒一点风险，换更多金币"这种选择根本不存在，熟练玩家只能干等。

## Solution

- **自动开波**：一波打完（全部出完、场上清空）后，开始 3 秒倒计时，到时自动开下一波。玩家在倒计时期间可以点按钮立即开始。第 1 波仍然由玩家手动开始，给开局建塔留出时间。
- **提前叫波**：当前波全部出完后，即使场上还有敌人，玩家也可以提前叫下一波，按叫波那一刻场上存活的敌人数获得金币奖励。不允许两波同时出怪。
- **HUD**：仍然只有一个按钮，文字随状态变化，玩家随时知道现在能做什么、提前叫能拿多少。

## User Stories

### 玩家

1. 作为玩家，我希望一波打完后，下一波会在几秒后自动开始，这样我不用每次都去点按钮。
2. 作为玩家，我希望在自动开波之前，按钮上能看到倒计时，这样我知道还有多少时间可以建塔或升级。
3. 作为玩家，我希望倒计时期间点按钮就能立即开始下一波，这样我准备好了就不用干等。
4. 作为玩家，我希望第 1 波由我自己决定什么时候开始，这样开局有足够时间布置防线。
5. 作为玩家，我希望倒计时期间可以照常建塔、升级、卖塔，这样短暂的间隙也能用上。
6. 作为玩家，我希望当前波全部出完后，即使场上还有敌人，也能提前叫下一波，这样我可以用风险换节奏。
7. 作为玩家，我希望提前叫波能拿到金币奖励，而且场上敌人越多奖励越多，这样冒的风险越大、收益越大。
8. 作为玩家，我希望叫波之前，按钮上就显示这次能拿多少奖励（例如"提前开波 +12"），这样我能判断值不值得。
9. 作为玩家，我希望拿到奖励时，在金币数旁边看到"+12"飘起来，这样我清楚地知道奖励到账了。
10. 作为玩家，我希望在敌人还在出时按钮是灰的，并显示"出怪中"，这样我知道现在为什么不能叫波。
11. 作为玩家，我希望最后一波开始后按钮显示"最后一波"并变灰，这样我知道没有下一波了。
12. 作为玩家，我希望游戏结束后不会再自动开波，这样胜负画面不会被打扰。
13. 作为玩家，我希望在倒计时里点按钮（场上已经清空）不会拿到奖励，这样奖励只给真正冒了风险的提前叫波。

### 开发者

14. 作为开发者，我希望倒计时和提前叫波的规则都在 Simulation 里，并且以 tick 计时，这样它们是确定性的，可以用测试和 `pnpm balance` 的脚本打法覆盖。
15. 作为开发者，我希望能从游戏状态里读到距离自动开波还剩多少 tick，这样 HUD、Debug overlay 和测试都能直接用。
16. 作为开发者，我希望有一个只读查询返回"现在叫下一波能拿多少奖励"，这样 HUD 不用自己计算。
17. 作为开发者，我希望 `waveStarted` 事件能说明这一波是玩家叫的还是自动开的、拿了多少奖励，这样 HUD 和以后的统计都能区分。
18. 作为开发者，我希望倒计时时长和每只敌人的奖励写在关卡定义里，并且有默认值，这样不同关卡可以有不同的节奏，现有关卡也不用改。
19. 作为开发者，我希望 `pnpm balance` 增加一个"每次都提前叫波"的参考打法，这样能看出奖励是否太高。

## Implementation Decisions

### 关卡定义

- 新增两个可选字段，都有默认值：
  - **自动开波倒计时秒数**：默认 3。
  - **提前叫波时每只存活敌人的奖励金币**：默认 1。
- 现有的第 1 关不用写这两个字段，直接用默认值。

### Simulation 规则

- **能不能开下一波**：游戏进行中、当前波已全部出完、而且还有下一波。不再要求场上没有敌人。第 1 波之前也满足这个条件。
- **提前叫波**：开波时场上还有存活敌人，就算提前叫波。奖励 = 场上存活敌人数 × 关卡里的每只奖励，立即加到金币上。场上没有敌人时，奖励为 0。
- **自动开波倒计时**：
  - 第 1 波之后的每一波，在"当前波全部出完、场上清空、还有下一波"这三个条件同时满足的那个 tick，开始倒计时，时长为关卡的倒计时秒数换算成 tick。
  - 倒计时每 tick 减 1，到 0 时自动开下一波：没有奖励，因为场上已经清空。
  - 玩家在倒计时期间开波时，倒计时取消。游戏结束时，倒计时也取消。
  - 第 1 波之前没有倒计时；最后一波之后也没有（游戏直接判胜）。
- **游戏状态**：波次进度里新增"距离自动开波还剩多少 tick"，没有倒计时时为 null。
- **公开接口**：
  - `startNextWave()` 成功时返回本次奖励（可能是 0），不能开波时返回失败。
  - 新增只读查询"现在叫下一波能拿多少奖励"：不能开波时返回 0。
  - `canStartNextWave()` 保留，按新条件判断。
- **事件**：`waveStarted` 增加两个字段：奖励金额，以及这一波由谁触发（玩家或自动）。
- **胜负判定不变**：最后一波全部出完、场上清空就判胜。

### HUD

- 仍然只有一个开波按钮，文字和可点状态由 Simulation 的状态和查询决定，HUD 不自己判断规则：

  | 状态 | 按钮文字 | 可点 |
  |---|---|---|
  | 第 1 波之前 | 开始第 1 波 | 是 |
  | 当前波还在出怪 | 出怪中 | 否 |
  | 出怪完毕、场上还有敌人 | 提前开波 +X（金币色） | 是 |
  | 倒计时中 | 下一波 N（N 为向上取整的剩余秒数） | 是 |
  | 最后一波已开始 | 最后一波 | 否 |

- 提前叫波拿到奖励时，在 HUD 的金币数旁边飘出"+X"，约 0.6 秒后淡出。它由 `waveStarted` 事件里的奖励金额触发，只用 Theme tokens。
- 不做屏幕中央的大倒计时。

### Debug overlay

- 倒计时进行中时，显示剩余秒数。

### 平衡报告

- 现有的脚本打法本来就是"一能开波就开"。新规则下，"能开波"的时机提前到"当前波出完"，所以这些打法要显式等场上清空再开波（也就是靠自动开波或在倒计时里开），保持原来的含义。之后确认现有验收标准仍然全部通过。
- 新增参考打法"混合打法 A，每次都提前叫波"：当前波一出完就叫下一波。只记录结果（输赢、剩余生命、累计奖励），不设硬性标准。如果它满血通关并且多拿了很多金币，就调低每只敌人的奖励或者调整关卡，并在工单里说明。

### 文档

## Testing Decisions

- **好的测试**：只通过 Simulation 的公开接口观察行为，用 Fixture 构造初始状态，倒计时时长和奖励系数从关卡定义里读取，不写死。
- **需要覆盖的规则**（参考现有的"开波""胜利"测试）：
  - 当前波出完、场上清空后开始倒计时，倒计时的 tick 数对得上；到 0 时自动开波，`waveStarted` 的触发方式是"自动"、奖励为 0。
  - 第 1 波之前没有倒计时；最后一波之后没有倒计时，直接判胜。
  - 倒计时期间玩家开波：立即开始，没有奖励，倒计时清空。
  - 当前波还在出怪时不能开波；出完后，即使场上还有敌人也能开波，奖励 = 存活敌人数 × 系数，金币立即增加。
  - 只读奖励查询和实际拿到的奖励一致；不能开波时返回 0。
  - 游戏结束时倒计时取消，也不再自动开波。
  - 关卡没写这两个字段时用默认值；写了就用写的值。
- 现有"场上有敌人时不能开波"的测试，改成表达新规则。
- **视觉**：用 story 冒烟测试和 Shots 检查。
  - HUD 按钮的五种状态，各有一个 story。
  - 金币飘字用 `effects` 冻结在第一帧。
  - 一个"提前叫波"的 Scenario，带 Shot 时间线。
- **关卡**：用 `pnpm balance` 的报告验收，不写成断言。

## Out of Scope

- 两波同时出怪（在当前波出怪时叫下一波）。
- 游戏加速和暂停（另行列入路线图）。
- "自动开波"的开关或设置项。
- 屏幕中央的大倒计时、开波音效。
- 预告下一波有哪些敌人。
